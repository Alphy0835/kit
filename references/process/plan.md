# Нарезать цель на задачи

Открывай, когда режешь цель, ТЗ или пачку находок на задачи исполнителям.

Статус: черновик от 16.10.2026, не испытан.
Как писать само задание — `process/task.md`. Новый проект, подпроект или фича на несколько модулей — сначала
спецификация, `process/spec.md`: первая задача тогда каркас по карте модулей.

## 1. Задачи вместе покрывают цель и не пересекаются

Выпиши, что должно быть в итоге. Каждая строка итога принадлежит ровно одной задаче. Строка, которую одна задача
отдала другой, должна стоять в критериях второй.

Переносишь экран, раздел или модуль — в критерии строка «всё, что было, на месте» со списком того, что было:
поля, кнопки, настройки.

Почему. Две задачи пересборки меню: первая отдала общие настройки второй, вторая перечислила только две из них.
48 настроек пропали из панели, обе задачи приняты. Через две недели при той же пересборке нашлись кнопки
без вызова. Правило 100 % из WBS: части дают весь объём родителя, лишнего нет.

## 2. Размер — одна сессия исполнителя

Задача — то, что исполнитель сделает и проверит в одной сессии без сжатия контекста. Ориентир правки — до
400 строк. Больше — режь по результатам, а не по слоям.

Почему. У агентов успех падает с длиной задачи: почти всегда справляются с задачей на минуты человека, редко —
на часы. Ревью правки больше 400 строк находит заметно меньше. В нашем проекте строки на задачу выросли вдвое,
и 100 строк подорожали в 1,6 раза.

## 3. Две задачи на один список — одна задача или по очереди

Список, общий для двух мест: причины в коде и подписи в панели, ключи настроек и копия в миграциях, коды
ошибок и их тексты. Если одна задача добавляет в список, а другая читает его, — либо это одна задача, либо вторая
ставится после слияния первой, и в её критериях есть «все значения списка известны».

У параллельных задач с локальным запуском — разные порты.

Почему. Три пропуска приёмки: две задачи слиты в один день, каждая зелёная, а вместе панель показывает служебный
ключ вместо подписи. Один порт на две параллельные задачи дал двойную работу.

## 4. Внешняя система — сначала запись настоящего ответа

Код против портала, платёжки, мессенджера или чужого API начинается с записи его настоящего ответа: снятый
запрос и ответ кладутся в тесты как образец. Записи нет и снять её нельзя — в критериях проверка вживую, с тем,
кто и где её делает.

Почему. Семь пропусков: код написан по документации, а портал отвечал другим ключом, другим полем, без поля
вовсе. Один такой дефект прожил три с половиной недели: настоящий ответ попал в тесты только тогда.

## 5. Роль — по сути задачи

«Обсудить», «решить», «спланировать» — работа тим лида, не исполнителя. Исполнителю — то, что меняет код или
документы проекта.

## Когда не применять

Правило 1 — для одиночной правки без связи с другими задачами. Правило 4 — если система уже записана в тестах и
правка её не меняет.

## Что из этого проверяет скрипт

Ничего.
