# Журнал изменений и заметки о выпуске

Открывай, когда записываешь, что изменилось в версии: для разработчиков — журнал изменений, для
пользователей и заказчика — заметки о выпуске.

## Чем они отличаются

| | Журнал изменений | Заметки о выпуске |
|---|---|---|
| Читатель | Тот, кто обновляет и сопровождает | Тот, кто пользуется |
| Полнота | Каждое заметное изменение | То, что читатель увидит или должен сделать |
| Язык | Термины кода допустимы | Слова с экрана |

## Журнал изменений

Формат Keep a Changelog:

- Файл `CHANGELOG.md` в корне проекта.
- Сверху раздел «Не выпущено»: туда пишется по ходу работы.
- На каждую версию — заголовок «версия — дата». Дата в виде ГГГГ-ММ-ДД. Новая версия сверху.
- Внутри версии изменения собраны по видам, в этом порядке:

| Вид | Что туда идёт |
|---|---|
| Добавлено | Новые возможности |
| Изменено | Изменения в том, что уже было |
| Устарело | То, что скоро уберут |
| Удалено | То, что убрали |
| Исправлено | Исправленные ошибки |
| Безопасность | Закрытые уязвимости |

- Журнал пишется для людей. Список сообщений коммитов — не журнал.
- Отозванная версия остаётся в журнале с пометкой.
- Сказано, по какому правилу растёт номер версии.

Шаблон. В угловых скобках — место для своего текста:

```
## [Не выпущено]

## [<версия>] — <ГГГГ-ММ-ДД>

### Добавлено
- <Что появилось>.

### Изменено
- <Что работает иначе и как было>.

### Исправлено
- <Что было не так> — <что стало>.
```

Номер версии по SemVer — три числа:

| Число | Растёт, когда |
|---|---|
| Первое | Изменение ломает совместимость |
| Второе | Добавлена возможность, старое работает |
| Третье | Исправлена ошибка, поведение то же |

## Заметки о выпуске

Разделы по шаблону The Good Docs Project:

1. Заголовок: продукт и номер версии.
2. Новые возможности.
3. Новые возможности, после которых нужно что-то настроить.
4. Улучшения.
5. Исправленные ошибки.
6. Известные проблемы.
7. Что устарело и когда уберут.

Правила текста из руководства Red Hat:

- Текст написан с точки «сразу после обновления». Прошлое — в прошедшем времени, новое — в настоящем.
- «До этого обновления», а не «раньше». Слова «теперь» нет.
- Исправленная ошибка идёт цепочкой: причина, следствие, что исправили, что стало.
- Известная проблема: причина и следствие в настоящем времени, затем обходной путь командой либо слова
  «обходного пути нет».
- Будущие исправления не обещаются.
- Заголовок заметки — до 120 знаков, без точки.

Шаблоны записей:

```
Новая возможность:   <Кто> может <что> <где>. <Что настроить — когда нужно.>
Исправление:         До этого обновления <что происходило> <при каком условии>. <Что происходит сейчас.>
Известная проблема:  <Что происходит> при <условии>. <Обход: команда либо действие | Обходного пути нет.>
Устарело:            <Что> будет убрано в версии <N>. Замена — <что>.
```

Было: «Исправлены различные ошибки».
Стало: «До этого обновления бот не отвечал на команду `/start` после перезапуска сервера. Бот отвечает сразу
после запуска».
