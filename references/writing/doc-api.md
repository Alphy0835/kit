# Документация API, которая собирается сама

Открывай, когда пишешь описания методов для страницы Swagger либо Redoc, комментарии в коде, из которых она
собирается, либо проверяешь файл OpenAPI. Справка, которую пишут руками, — `doc-reference.md`.

## 1. Что собирает машина и что пишет человек

Страница Swagger показывает файл OpenAPI. Файл собирается из кода. Из кода берётся каркас, смысл в каркас
вписывает человек. Слова с встречи у заказчика владельца 24.09.2026: «автоматом он описания не сделает, его
надо заполнять».

| Что | Кто |
|---|---|
| Адрес и HTTP-метод | Машина |
| Имя, тип и обязательность параметра | Машина |
| Схема тела запроса и ответа, перечисления | Машина |
| Код успешного ответа | Машина; 201 и 204 называет человек |
| Ошибка проверки входных данных, код 422 в FastAPI | Машина |
| Остальные ошибки: 401, 403, 404, 409 | Человек |
| Название и версия API, общее описание | Человек |
| Короткое название метода и его описание | Человек |
| Описание каждого параметра и поля | Человек |
| Примеры запроса и ответа | Человек |
| Раздел, в котором стоит метод, и описание раздела | Человек |
| Пометка «устарел» | Человек |

Машина следит, чтобы каркас совпадал с кодом. За тексты, список ошибок и примеры отвечает человек: расходятся
с кодом именно они.

## 2. Обязательный минимум

Требования сведены из руководств Google, Microsoft, Zalando, Stripe, GitHub и шаблона The Good Docs Project.

**Метод:**

1. Короткое название: что метод делает.
2. Описание: когда его вызывать, что происходит при успехе, какие есть побочные действия.
3. Кому доступен: роль либо право.
4. Все параметры и поля тела с описанием.
5. Успешный ответ: схема и пример.
6. Известные ошибки: код и условие, при котором он приходит.
7. Пример запроса, который можно скопировать и выполнить.
8. Имя операции — постоянное и неповторимое: по нему клиенты называют функции.

**Параметр и поле:**

1. Назначение. Имя и тип в описании не повторяются.
2. Единица измерения и формат: секунды, копейки, дата в виде ГГГГ-ММ-ДД.
3. Допустимые значения и пределы. Сказано, входит ли граница.
4. Значение по умолчанию.
5. Для строки — длина. Сказано, что будет с длинной строкой: обрезается либо отклоняется.
6. Для флага — что происходит при «да» и что при «нет».
7. Может ли поле отсутствовать либо быть пустым.

**Ошибка:**

1. Вид ошибки один на весь API и описан на общей странице.
2. У каждого кода названо условие.
3. Текст ошибки короткий и говорит, что исправить. Внутреннего устройства в нём нет: имён таблиц, следа вызовов.
4. Для программы есть постоянный код ошибки. Программа не разбирает текст.

**Пример:**

1. Пример совпадает со схемой.
2. Пример полный: его можно скопировать.
3. Настоящих ключей, паролей, телефонов, имён и внутренних адресов в примере нет: раздел 8.

**Устаревший метод либо параметр:** пометка, причина, замена, дата отключения.

## 3. Как писать описание

Шаблон. В угловых скобках — место для своего текста:

```
Короткое название:  <Глагол в неопределённой форме> <предмет>
Описание:           <Глагол в третьем лице> <предмет> и <побочное действие>. <Когда вызывать.>
                    Доступно: <роль либо право>.
Параметр:           <Что это>. <Единица и формат>. От <мин> до <макс> включительно. По умолчанию <значение>.
Флаг:               Да — <что происходит>. Нет — <что происходит>. По умолчанию <да | нет>.
Ответ:              Возвращает <что>.
Ошибка:             <Код> — <условие, при котором она приходит>.
Устарело:           Устарел. Замена — <что>. Отключение <ДД.ММ.ГГГГ>.
```

**Короткое название метода** — заголовок и строка меню на странице.

- Глагол и предмет, без точки: «Создать заказ».
- До 5–6 слов. Имя функции не повторяет.

**Первая фраза описания.** В списках и подсказках показывают только её.

- Начинается с глагола в третьем лице: «Создаёт заказ и резервирует товары на складе».
- Слов «этот метод», «данная функция» нет.
- Сокращений с точкой внутри фразы нет: «т. е.» обрывает её в подсказке.
- Устаревший метод: «Устарел. Замена — `POST /v2/orders`. Отключение 01.03.2027».

**Описание параметра.**

Было: «`limit` — лимит».
Стало: «Сколько заказов вернуть. От 1 до 100 включительно. По умолчанию 20».

Было: «`amount` — сумма».
Стало: «Сумма заказа в копейках. Целое число от 1».

Было: «`notify` — флаг уведомления».
Стало: «Да — клиент получает письмо о заказе. Нет — письмо не отправляется. По умолчанию да».

**Описание ответа.** «Возвращает созданный заказ». Слов «Successful Response», которые FastAPI ставит сам, на
странице не остаётся.

**Описание ошибки.** «404 — заказа с таким номером нет либо он принадлежит другому клиенту».

**Оформление.** В описаниях — простая разметка: абзацы, списки, код. Заголовков, таблиц и HTML нет: разные
программы показа выводят их по-разному. Имена полей и значения стоят моноширинным шрифтом. Ссылки полные.

Правила фразы — те же, что для справочника: `doc-reference.md` и `text-style-guides.md`.

## 4. Общая страница API

Собранная справка отвечает на вопрос «что принимает этот метод». На вопрос «с чего начать» она не отвечает.
Перед справкой нужна общая страница. В OpenAPI это общее описание API либо внешний документ по ссылке:

- что это за API и для кого;
- базовый адрес и среды: рабочая, проверочная;
- как получить доступ и как проходит авторизация;
- версия и правило, по которому она меняется;
- постраничная выдача и пределы частоты запросов;
- единый вид ошибки и таблица кодов;
- первый запрос: шаги от ключа до ответа, по `doc-howto.md`.

## 5. Где это пишется в коде

**FastAPI:**

| Что | Где |
|---|---|
| Название, описание и версия API | Аргументы `title`, `summary`, `description`, `version` у `FastAPI(...)` |
| Короткое название метода | Аргумент `summary` у декоратора |
| Описание метода | Комментарий-описание функции либо аргумент `description` |
| Описание успешного ответа | Аргумент `response_description` |
| Ошибки, кроме 422 | Аргумент `responses={404: {"model": ..., "description": ...}}` |
| Раздел | Аргумент `tags`; описания разделов — `openapi_tags` у приложения |
| Описание и пример параметра | `Query(...)`, `Path(...)`, `Header(...)` с `description` и `examples` |
| Описание и пример поля | `Field(description=..., examples=[...])` в модели Pydantic |
| Описание модели | Комментарий-описание класса |
| Устаревшее | `deprecated=True` |
| Скрыть служебный метод | `include_in_schema=False` |

Заметки для себя в комментарии функции отделяются знаком `\f`: текст после него на страницу не попадает.

**NestJS, пакет `@nestjs/swagger`:**

- Раздел ставится сам по имени контроллера.
- Поля попадают в схему с пометкой `@ApiProperty()` либо через плагин сборки.
- Комментарии к методам и полям становятся описаниями только при настройке `introspectComments: true`. По
  умолчанию она выключена.
- Ответы с ошибками называются пометками `@ApiResponse`.

## 6. Что проверяет линтер

Линтер проверяет, что описание есть и что файл устроен верно. Смысл он не видит.

| Что проверяется | Spectral | Redocly CLI |
|---|---|---|
| У метода есть описание | `operation-description`, включено | `operation-description`, выключено |
| У метода есть короткое название | правила нет, пишется своё | `operation-summary`, включено |
| Имя операции есть и не повторяется | `operation-operationId`, `operation-operationId-unique` | те же имена |
| У параметра есть описание | `oas3-parameter-description`, выключено | `parameter-description`, выключено |
| У метода есть раздел, раздел описан | `operation-tags`, `operation-tag-defined`; `tag-description` выключено | `operation-tag-defined`, `tag-description` |
| Пример совпадает со схемой | `oas3-valid-media-example`, `oas3-valid-schema-example` | `no-invalid-media-type-examples`, `no-invalid-schema-examples`, `no-invalid-parameter-examples` |
| Есть успешный ответ | `operation-success-response` | `operation-2xx-response` |
| Есть ответ с ошибкой клиента | — | `operation-4xx-response` |
| У полей есть пример | — | `scalar-property-missing-example`, выключено |
| В описаниях нет опасной разметки | `no-script-tags-in-markdown`, `no-eval-in-markdown` | `no-unsafe-markdown` |

Выводы:

- Готовый набор «рекомендованных» правил не покрывает минимум из раздела 2. Правила с пометкой «выключено»
  включаются явно.
- Длину описания, точку в конце и начало с глагола встроенные правила не проверяют. В Redocly для этого пишут
  своё правило с наименьшей длиной и шаблоном.
- Описание, которое повторяет имя — «`timeout` — таймаут», — линтер пропускает. Его ловит только чтение.

Имена правил записаны по пересказу страниц. Перед тем как положить их в скрипт проверки, каждое проверяется
запуском на пробном файле.

## 7. Как не дать описанию разойтись с кодом

1. **Источник правды один.** Когда описание собирается из кода — это код. Файл OpenAPI в репозитории — его
   снимок. Править снимок руками нельзя.
2. **Снимок лежит в репозитории.** По нему видно, что изменилось в API за правку.
3. **Сборка проверяет снимок.** При каждой правке файл собирается заново и сравнивается с тем, что лежит в
   репозитории. Разница останавливает сборку.
4. **Линтер идёт в той же сборке.** Раздел 6.
5. **Ломающие изменения ищет программа.** `oasdiff breaking` сравнивает старый и новый файл. Команда
   `oasdiff changelog` выдаёт список изменений для заметок о выпуске.
6. **Ответы сверяются с описанием на работающем сервере.** Schemathesis сам строит запросы по файлу и
   проверяет, что код ответа описан, а тело совпадает со схемой.
7. **Описание правится в той же правке, что и код.** Задача на новый метод не принята, пока у него нет
   описаний, ошибок и примера.

Порядок из шагов 3–6 — предложение тим лида по описаниям инструментов. Целиком он не запускался.

## 8. Страница документации и безопасность

- Страница доступна только тем, кто вправе пользоваться API. Так требует OWASP API Security, пункт API9:2023,
  и правило заказчика владельца: «страница не в открытом доступе».
- В FastAPI страницы отключаются аргументами `docs_url=None`, `redoc_url=None`, `openapi_url=None`. Авторы
  FastAPI предупреждают: скрытая страница — не защита. Защита — проверка прав в самих методах.
- Служебные методы на страницу не попадают.
- Старые версии и забытые стенды с открытой страницей — отдельный риск из того же пункта OWASP.
- В ошибках нет следа вызовов и внутренних имён.

Что стоит в примерах:

| Нужно | Значение |
|---|---|
| Домен | `example.com`, `example.org` |
| Адрес сервера | `192.0.2.1`, `198.51.100.1`, `203.0.113.1` |
| Почта | `user@example.com` |
| Ключ | заглушка: `<ВАШ_КЛЮЧ>` |
| Имя и телефон | вымышленные |

## 9. Что решает команда

Источники здесь расходятся либо молчат. Колонка «Берём» — предложение тим лида от 14.10.2026, владелец её не
утверждал.

| Вопрос | Стороны | Берём |
|---|---|---|
| Язык описаний | Google и Zalando — английский | Русский: описания читают люди заказчика. Имена полей и операций — английские |
| Форма короткого названия | Google — «Создаёт…», The Good Docs Project — «Создать…» | Название — «Создать заказ», первая фраза описания — «Создаёт…» |
| Вид ошибки | RFC 9457, свой вид у Google, у Azure, у Stripe | RFC 9457: поля `type`, `title`, `status`, `detail` |
| Сначала описание либо сначала код | OpenAPI Initiative и Zalando — сначала описание | Сначала код: так собирают FastAPI и NestJS. Взамен обязательны шаги 3–6 раздела 7 |
| Перечислять ли все коды ошибок | Zalando — известные перечислить, общие закрыть ответом по умолчанию. Azure — не перечислять | Перечислять те, на которые клиент отвечает по-разному |
