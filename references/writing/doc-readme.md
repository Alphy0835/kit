# README

Открывай, когда пишешь первый файл, который видит человек в репозитории или в папке проекта.

## Что должно быть

Обязательные разделы по Standard Readme, в этом порядке:

| Раздел | Что в нём | Правило |
|---|---|---|
| Название | Имя проекта | Совпадает с именем репозитория и пакета |
| Краткое описание | Что это и для чего | Одна строка, короче 120 знаков, без оценок |
| Содержание | Ссылки на разделы | Обязательно, если файл длиннее 100 строк |
| Установка | Команды в блоке кода | Названы версии и то, что нужно поставить заранее |
| Использование | Короткий пример с ожидаемым выводом | Пример запускается |
| Как участвовать | Куда писать о проблеме, как прислать правку | — |
| Лицензия | Название лицензии и владелец | Последний раздел |

Для внутреннего проекта без посторонних участников разделы «Как участвовать» и «Лицензия» заменяются одной
строкой: кто отвечает и куда писать.

Шаблон. В угловых скобках — место для своего текста:

````
# <Имя проекта>

<Что проект делает — одна строка короче 120 знаков.>

<Для кого он — одна фраза.>

## Установка

Нужно заранее: <программа и версия>.

```
<команда установки>
```

## Использование

```
<команда запуска>
```

Что получится: <ожидаемый вывод>.

## Документация

<Где лежит остальное — ссылкой.>

## Кто отвечает

<Имя либо роль>, <куда писать>.
````

## Что добавляют другие шаблоны

- Для кого проект: одна фраза сразу после описания.
- Чем проект отличается от похожих.
- Настройка и запуск отдельно от установки.
- Частые неполадки: три-пять случаев либо ссылка на страницу.
- Где лежит остальная документация.
- Состояние проекта: развивается, только исправления, заброшен.

## Правила

- Первая строка описания отвечает на вопрос «что это делает», а не «какое оно».
  Было: «Универсальное решение для автоматизации бизнеса».
  Стало: «Telegram-бот, который напоминает клиентам о записи и принимает подтверждения».
- Пишется для человека, который видит проект впервые. Установка расписана по шагам.
- Длинное уходит в папку документации, в README остаётся ссылка.
- Битых ссылок нет. Команды из README проверены на чистой машине.
- README пишется до первого показа проекта, а не после.
