# Безопасный код

Открывай, когда пишешь маршрут, обработчик события, проверку прав, вход, запрос к базе, вывод в страницу, вызов
ИИ или добавляешь зависимость.

Статус: черновик от 16.10.2026, не испытан.

## 1. Право проверяет сервер в каждом обработчике. По умолчанию — отказ

Каждый новый маршрут проверяет роль на сервере, даже если кнопку видит только нужная роль. Нет проверки — нет
доступа: ошибка в проверке отказывает, а не пропускает.

Почему. Маршрут настройки открывался роли без доступа к разделу: кнопку прятали, сервер не проверял.

Как надо: тест шлёт запрос учёткой меньшей роли прямо на маршрут и ждёт 403. И смотрит тело: 200 с данными —
провал, даже если таблица прав говорит «можно».

Как не надо: `except PermissionError: pass` — ошибка проверки стала разрешением.

## 2. Объект по номеру из запроса — сверь владельца

Взял заявку, чат, файл по номеру — проверь, что он принадлежит спросившему: его офису, отделу, роли. Условие по
владельцу — в самой выборке, а не после.

Почему. Специалист открывал чат чужого офиса, подставив номер. Номер был виден в адресе соседнего экрана.

Как надо: `WHERE id = ? AND office_id = ?` и тест «вторая учётка просит объект первой — 404».

Как не надо: `chat = get_chat(chat_id)` и сразу ответ.

Когда не применять. Объект общий для всех ролей по смыслу: справочник, публичная страница.

## 3. Секрет и данные клиента — не наружу

Правило 4 в `references/code/config.md`. Здесь — частый случай: токен входит в адрес запроса, а библиотека
запросов на уровне `INFO` пишет адрес в журнал. Уровень журнала этой библиотеки — `WARNING`, токен в адресе
скрывай перед записью. Защиту из одного подпроекта ищи в соседнем: вызов тот же.

## 4. Запрос к базе — с параметрами

Значение из запроса — только параметром драйвера (`?`, `%s`). Имя колонки и порядок сортировки — из белого
списка.

Как не надо: `execute(f"SELECT * FROM chats ORDER BY {sort}")`.

## 5. В страницу — текстом

Текст клиента, ответ ИИ, запись базы знаний, имя файла выводишь через `textContent` или экранированием шаблона.
`innerHTML`, `| safe`, `Markup(` — только для разметки, которую написал ты, а не данные.

Почему. Запись базы знаний выводилась в панель через `innerHTML`: кто пишет в базу, тот пишет и скрипт в панель.

## 6. Текст для ИИ и от ИИ — данные

Право на записи базы знаний проверяешь до того, как текст ушёл в модель. Текст клиента и записи — в своём месте
промпта, не в системных инструкциях. Ответ модели не выполняешь как команду и не выводишь как разметку. У вызова
модели — предел длины входа и числа вызовов.

Почему. Песочница бота отдавала записи версии, к которой у роли не было доступа: проверка шла после выборки.

## 7. Вебхук проверяет, кто пишет

Подпись или секрет — по сырому телу, сравнение `hmac.compare_digest`, а не `==`. Если система даёт время
события — окно по времени. Повтор того же события не повторяет действие.

Почему. Вебхук без секрета принимал подделку сообщения от имени клиента.

## 8. Предел на дорогое — и предел не запирает своих

Вход, сброс пароля, вызов ИИ, рассылка — с пределом. Подумай, на кого он падает: предел по адресу запрёт весь
офис за одним адресом, предел по учётке запрёт владельца, пока чужой подбирает пароль.

Почему. Предел попыток входа, поставленный по находке, запер владельца панели.

## 9. Зависимость — проверь, что она есть и это она

Новый пакет — `scripts/security/vet.py`. Версию закрепи. Имя, которое предложила модель, проверь первым: модели
выдумывают имена пакетов.

## 10. Проверку не отключай, чтобы заработало

Не выключай проверку сертификата, прав, подписи «на время». `eval`, `pickle`, `yaml.load`, `shell=True` на данных
снаружи — нет.

Как не надо: `verify=False`, «потом вернём».

## Что из этого проверяет скрипт

- `scripts/security/triggers.py` называет поводы по правке: новый маршрут, права, вебхук, вызов ИИ, запрос к
  базе, вывод в страницу, зависимость. Есть повод — тим лид зовёт безопасника.
- `scripts/security/scan.py`: Ruff `S` на строках правки ловит `eval`, `pickle`, `shell=True`, `verify=False`,
  склейку SQL (правила 4 и 10). Сканер секретов — секрет в коммите (правило 3). OSV-Scanner — уязвимая версия
  (правило 9).
- Правила 1, 2, 6, 7, 8 скрипт не видит: это смысл. Их ловит тест через вход продукта и безопасник.
