# Экран и сервер

Открывай, когда экран зовёт сервер: читает, сохраняет, удаляет. И когда меняешь элемент, который отправляет
значение.

Статус: черновик от 19.10.2026, не испытан.

## 1. Контракт — из кода сервера, а не догадкой

Адрес, метод, имена полей, виды значений (`widget` или `website`, число или строка) берёшь из кода маршрута и
документа API. Не нашёл — это вопрос, а не догадка.

Почему. Экран слал имя канала `website`, а сервер знал только `widget`: на тестах с подменой всё сходилось.

## 2. Заменил элемент — запрос остался прежним

Меняешь поле, список, переключатель на новый элемент — сравни запрос до и после: те же имена полей, тот же вид
значения, то же пустое значение («не задано» — пустая строка, `null` или поля нет вовсе). Возьми прежний запрос
из кода или из сети браузера и сравни с новым на каждом значении, включая пустое.

Почему. Новый элемент отличается от старого мелочью, которую сервер не прощает, а тесты сервера её не видят:
они шлют запрос сами.

## 3. Ответ сервера с ошибкой — не тишина

Каждый вызов обрабатывает отказ: показывает причину (`ui/states.md`, правило 6), возвращает кнопку в рабочий
вид, не делает вид, что сохранено. «Сохранено» — только после ответа об успехе.

## 4. Сервер решает, экран только показывает

Права, проверка ввода, итог расчёта — на сервере. Спрятанная кнопка не защищает маршрут: проверка роли — на
сервере в каждом обработчике (`code/security.md`, правило 1). Экран может проверить ввод раньше, чтобы
подсказать, но не вместо сервера.

## 5. Один источник данных

Список, который уже грузит другой экран продукта, берёшь оттуда же, тем же вызовом. Вторую копию загрузки и
свой кэш того же списка не заводишь.
