# Обновить базу типовых проверок

Открывай, когда владелец зовёт безопасника без задачи и просит обновить базу. Это отдельный чат, не проверка
правки.

Статус: черновик от 17.10.2026, не испытан.

## 1. Что обновляем

В базе (`references/security/base/`) — виды ошибок в коде, а не отдельные дыры. Свежие уязвимости в чужих
библиотеках база не хранит: их OSV-Scanner берёт из общей базы при каждом запуске `scan.py`.

Новый вид ошибки — повод для записи, если он бывает в коде, который пишут наши исполнители, на нашем стеке.

## 2. Где смотреть

- Новые выпуски перечней: OWASP Top 10, OWASP ASVS, OWASP API Security Top 10, OWASP Top 10 for LLM
  Applications, CWE Top 25. Смотри, что добавлено с прошлого обновления, — дата прошлого внизу этого файла.
- Листы OWASP Cheat Sheet Series по нашему стеку: FastAPI, вебхуки, Docker, секреты, ИИ-агенты, RAG.
- Разборы дыр от крупных команд за последние месяцы: Anthropic, OpenAI, Google, GitHub Security Lab.
- Наши возвраты и находки безопасника с прошлого обновления: вид, который повторился дважды, — запись.

Только первоисточники. Пересказ в блоге без ссылки на первоисточник — не основание.

## 3. Как вносить

1. Сначала поиск по базе: такой вид уже есть? Есть — уточни поля записи, новую не заводи.
2. Новая запись — в группу по смыслу, по формату из `base/README.md`. Своими словами, без копирования чужих
   правил.
3. Ловится шаблоном — «Проверка: скрипт» с правилом. Правила ещё нет — «агент» и строка владельцу: какую
   проверку стоит добавить в `scan.py`.
4. Новая группа — свой файл с «Строки:» и «Пути:». Проверь: `python scripts/security/checks.py` на любой ветке
   печатает её без ошибки.
5. Источник записи — в `docs/basis/security.md`, не в файл базы.
6. Запись больше не нужна (вид исчез вместе со стеком) — удали и скажи владельцу.
