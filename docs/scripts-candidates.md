# Что заменить скриптами и хуками

Замер 24.10.2026 по журналам чатов «Рабочей» за 17–24.10: 321 чат, 17 980 вызовов инструментов, 83 принятые
задачи. Цена вызова — токены сообщения модели, где он стоит, с весами: вход 1, запись кэша 1,25, чтение кэша
0,1, выход 5. Всего за неделю — 356 млн взвешенных токенов.

Главное. Скрипт экономит не столько вывод команды, сколько шаги модели: каждый вызов — новый проход по всему
контексту чата. Пять вызовов, которые делает один скрипт, — четыре лишних прохода.

## Что не заменить

Чтение и правка кода, поиск по коду, ревью диффа, субагенты — 55% токенов недели. Это работа с суждением,
скриптом её не заменить.

## Кандидаты, по убыванию цены

### 1. Учёт задач: статус, список, история, конфликты в списке

Сейчас: 1281 вызов, около 25 млн (7%). Из них поиск строк в списке задач — 759, правка строк — 155, конфликты
в списке при слиянии — 170, статус в файле задания — 68, обзор веток — 111. У тим лида это около семи вызовов на
каждую принятую задачу, и почти все на старшей модели: он каждый раз пишет одноразовый скрипт на Python, чтобы
вставить строку или перенести её в историю.

Что сделать в kit:
- Исполнитель список задач не правит. Статус живёт только в файле задания, список собирает скрипт. Конфликтов в
  списке при слиянии тогда нет совсем.
- `scripts/lead/tasks.py` уже читает список. Добавить команды: показать одну задачу, поставить статус, принять
  (слить ветку, поставить DONE, перенести в историю с датой, закоммитить).

### 2. Старт задачи одной командой

Сейчас: около 1200 вызовов, около 19 млн (5%). Заведение рабочей копии — 153, чтение регламента и решений — 679,
чтение задания — 362. Плюс проверка ветки и статуса git — 528 вызовов, 11 млн, часть из них на старте.

Что сделать: `start.py <задача>` заводит рабочую копию и ветку, берёт порт из задания и печатает то, что
исполнитель обязан прочитать: задание, записи из поля «Решения», разделы правил для роли. Один вызов вместо
десятка.

### 3. Браузер: снимки на двух ширинах

Сейчас: 1279 вызовов, около 22 млн (6%), почти всё у фронтенда. Смена ширины, переход, снимок, проверка — по
одному вызову на каждое действие.

Что сделать: в `scripts/qa/stand.py` уже есть браузер и снимок. Добавить команду, которая снимает список
адресов на 1280 и 375 px за один вызов и кладёт файлы рядом с отчётом.

### 4. Стенд: поднять, дождаться, завести учётку

Сейчас: 716 вызовов, около 17 млн (5%), почти 4 часа ожидания. Запуск сервера, `sleep`, `curl` на проверку
живости, поиск занятого порта, заведение локальной учётки — по одному шагу.

Что сделать: `up.py <задача>` поднимает стенд на порту задачи, ждёт ответа, заводит тестовую учётку и печатает
адрес и файл учёток. Команды запуска проект называет в `kit.toml`.

### 5. Ожидание CI на GitHub

Сейчас: 202 вызова, около 3 млн, около 3 часов, почти всё — тим лид на старшей модели. Он запускает прогон и
опрашивает его по кругу.

Что сделать: `ci.py` запускает прогон, ждёт его в одной команде и печатает одну строку итога и имена упавших
тестов.

### 6. Хуки вместо памяти модели

- Перед `git commit`: ветка совпадает с задачей, в команде нет `add -A` и `stash`. Сейчас ветку проверяют
  руками — до 528 вызовов в неделю, — а коммит всё равно уезжал на чужую ветку.
- Перед запуском тестов: в сессии уже была правка кода. Правило «тесты не на старте» нарушали по привычке.

## Уже есть в kit

Тесты: 1113 вызовов, около 30 млн (8%), 17 часов. В kit их выбирает и гоняет `scripts/handoff/tests.py`, а с
24.10 действует правило «один прогон после всех правок». В «Рабочей» этого скрипта нет.

## Сколько можно сэкономить

Пункты 1–5 вместе — около 86 млн из 356 (24%) токенов недели. Целиком они не уйдут: скрипт заменяет несколько
вызовов одним, а не ноль. Ожидаемо — половина, около 12% недельного расхода команды. Главная доля — у тим лида,
он работает на старшей модели.

## Ограничения замера

- Действия разнесены по видам регулярными выражениями по тексту команды. Отдельные вызовы попали не туда, порядок
  цифр от этого не меняется.
- Около четверти вызовов субагентов — пробы безопасника на копиях задач, а не обычная работа.
- Время вызова — до следующего шага модели, в него входит и её обдумывание.
