# Группа AC. Права маршрута, чужой объект, лишние поля

Строки: `@\w+\.(?:get|post|put|patch|delete|route|websocket|api_route)\(|APIRouter\(|Depends\(|dependencies\s*=|permission|role|owner|user_id|office|WHERE\s+id\s*=|\.get\(\s*\w*_?id`
Пути: `*routes* *api* *views* *permissions*`

### AC-1. Объект по номеру без сверки владельца
Проверка: агент
Признак: маршрут берёт номер объекта из пути, тела или параметра и читает или меняет объект, не сверив
владельца, офис, роль. Список фильтрует по владельцу, а карточка или правка — нет.
Не ошибка: выборка содержит условие по владельцу из сессии; номер — длинный случайный и нигде не виден другим.
Как закрыть: условие владельца в самом запросе к базе, владелец — из сессии, не из запроса. Нет — 404.
Класс: 1

### AC-2. Новый маршрут без проверки права
Проверка: агент
Признак: у нового обработчика нет зависимости проверки права, а у соседних в том же разделе — есть. Или право
слабее, чем у соседнего маршрута с тем же действием.
Не ошибка: маршрут открыт намеренно, и это записано в задании или спецификации.
Как закрыть: то же право, что у соседних маршрутов раздела; строка в тесте-переписи маршрутов.
Класс: 2

### AC-3. Роль, владелец или офис берутся из запроса
Проверка: агент
Признак: `user_id`, `role`, `office_id`, `is_admin` приходят в теле или параметре и используются как «кто
спрашивает».
Не ошибка: значение берётся из сессии; из запроса — только «над кем действие», и оно проверяется.
Как закрыть: кто спрашивает — только из сессии.
Класс: 1, 2

### AC-4. Модель принимает поля, которые роль менять не вправе
Проверка: агент
Признак: в модель обновления входят роль, владелец, статус, цена, флаги; данные из запроса пишутся в базу
целиком (`**payload`, `model_dump()`).
Не ошибка: отдельная модель на каждую роль, лишние поля отвергаются (`extra="forbid"`).
Как закрыть: модель только с разрешёнными полями.
Класс: 2

### AC-5. Ответ отдаёт поля, которые роли не положены
Проверка: агент
Признак: маршрут возвращает запись базы целиком; в ответе хэш пароля, токен, телефон, данные другого офиса.
Не ошибка: модель ответа перечисляет поля явно.
Как закрыть: `response_model` с явным списком полей для каждой роли.
Класс: 4

### AC-6. Проверка права в одной ветке кода, в соседней нет
Проверка: агент
Признак: в функции несколько путей (новый и старый режим, канал А и канал Б, повтор после сбоя), проверка
стоит только на одном.
Не ошибка: проверка стоит до развилки.
Как закрыть: проверка до развилки или в каждой ветке.
Класс: 1, 2

### AC-7. Ошибка проверки превращается в «разрешено»
Проверка: агент
Признак: `except` вокруг проверки права или подписи, после которого код идёт дальше; значение по умолчанию
«разрешено» при пустой настройке.
Не ошибка: любая ошибка проверки — отказ.
Как закрыть: по умолчанию отказ.
Класс: 2, 5

### AC-8. Действие меняет состояние по GET
Проверка: агент
Признак: удаление, отправка, смена статуса на маршруте `GET`.
Не ошибка: GET только читает.
Как закрыть: POST, PUT, DELETE с защитой от запроса с чужого сайта (`browser.md`, BR-4).
Класс: 2, 7
