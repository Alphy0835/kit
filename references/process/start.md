# Начало задачи

Открывай, когда берёшь задачу в работу: первая сессия, новая сессия по той же задаче или после сжатия контекста.

Статус: черновик от 18.10.2026, не испытан.

## 1. Сверь модель с полем «Модель» задания

Первый шаг — до чтения кода. Модель чата не совпадает с полем, в любую сторону, — остановись и скажи владельцу.
Сильнее указанной — тоже стоп: это его деньги.

Хук набора проверяет это раньше тебя: на команде `/<роль> <задача>` с чужой моделью команда до тебя не доходит.
Владелец отправил её второй раз, не переключив, — он выбрал модель нарочно, работай. Сменил модель посреди
работы — тоже его выбор, назад не проси.

Почему. Поле выбора модели помнит прошлый выбор. За две недели 41 сессия исполнителей из 135 ушла на старшую
модель, хотя в задании стояла младшая.

## 2. Своя рабочая копия и своя ветка

Задача ведётся в своей рабочей копии (`git worktree`) на ветке задачи. Общая папка остаётся на основной ветке:
в ней работают другие чаты.

Копию сам не заводи: это делает хук набора на команде `/<роль> <задача>`. Путь и ветку он пишет в начало чата.
Строки от хука нет — задачу дали словами — запусти `scripts/handoff/worktree.py <задача>`: он делает то же самое.
Хук или скрипт сказал «уже была» — посмотри последнюю запись журнала ветки из его строки. Чужие записи последних
часов — стоп и вопрос: задачу, возможно, ведёт другой чат.

Перед каждым коммитом смотри, на какой ты ветке. В коммит — только свои файлы, по именам.

Почему. Коммит уезжал на чужую ветку трижды, черновик терялся. Заведение копии стоило исполнителю несколько
вызовов на каждом старте — 153 вызова за неделю 17–24.10, — а команда каждый раз одна и та же. `git add -A` унёс чужие правки четырёх файлов,
`git stash` — один на все рабочие копии — отдал чужой дифф двум задачам.

Как не надо: `git add -A`, `git commit -a`, `git stash`, `git checkout <файл>` поверх своей работы.

## 3. Читай то, что назвало задание, а не всё подряд

Задание, спецификация (разделы из поля «Спецификация»), записи решений из поля «Решения». Журнал решений и его
сводку не читай: только записи из поля, каждую целиком. Регламент проекта — только разделы для своей роли.
Задание ссылается на файл — открой его. Владелец дал снимок или запись — открой их до работы.

Почему. Чтение на старте задачи стоило около 75 тыс. токенов, из них журнал решений — 57 тыс. Регламент целиком
ещё около 50 тыс. на каждый чат, а исполнителю из него нужна половина.

## 4. Код — туда, где ему место по карте

Спецификация с картой модулей есть — код ищешь сначала по ней: модуль из поля «Спецификация» и его соседи по
карте. По всему проекту ищешь, только если карты не хватило. Новый файл кладёшь в модуль из поля «Спецификация». Чужой модуль зовёшь
только через его вход и только если он есть в колонке «Может вызывать» твоего модуля. Нужен путь вне карты или
вызов, которого карта не разрешает, — стоп и вопрос тим лиду: сначала правится спецификация.

Почему. Без карты один механизм появлялся в двух файлах, 20 связей из 45 шли во внутренние файлы чужих модулей.

## 5. До первой правки тесты не запускаешь

Ветка взята от основной, а основную тим лид прогнал целиком при приёмке прошлых задач. Прогон на старте ничего
не находит. Как устроен тест — читаешь его файл, а не запускаешь.

Исключение одно: задача про сам тест — падающий или зависающий. Тогда один раз воспроизведи падение этим
файлом и с этого начинай.

Почему. За неделю в 27 чатах исполнителей из 129 тесты шли до первой правки, в 8 из них — весь набор. Время
и лимит ушли впустую, процессор был занят, соседние чаты ждали.

## 6. Доступ — из поля «Доступы» и карты доступов

Нужен ключ, вебхук, токен или учётка — открой блок с этим именем в карте доступов проекта (путь — `access` в
`kit.toml`, обычно `team/ACCESS.md`) и возьми значение там, где сказано. Поле «Доступы» задания называет, какие
блоки нужны; понадобился другой — тоже бери по карте.

По памяткам, отчётам, памяти, журналам чатов и чужим рабочим копиям доступ не ищи и скрипт для поиска не пиши.
В карте доступа нет или значения нет там, где сказано, — статус `BLOCKED` и вопрос владельцу.

Значение не печатай и не пиши в отчёт, код и коммит: в команде — имя переменной, проверка — по ответу системы.

Почему. 24–25.10 два чата искали вебхук Bitrix24 по памяткам встреч, отчётам, памяти и журналам других чатов,
один написал для этого скрипт. Значение было в настройках, а записать, где оно, никто не догадался.

## 7. Не можешь сделать — скажи, а не обходи

Задание противоречит коду, нужен доступ, которого нет, шаг необратим или от ответа зависит, что вообще делать, —
статус `BLOCKED` и вопрос. Обходной путь молча не ищи. Мелкая неясность — выбери прочтение ближе к тексту и
запиши допущение в отчёт (`process/handoff.md`, правило 3).

Ошибку в задании называй сразу и прямо, с доказательством: файл и строка, вывод команды. Проверил и ошибок нет —
не выдумывай.

## 8. Делаешь только задачу

Замеченное рядом — ошибку, старый код, неудачное имя — пиши в отчёт строкой для тим лида, а не чини.
Подробно — `code/changes.md`, правило 1.

## 9. После сжатия контекста

Перечитай задание, проверь рабочую копию и ветку (правило 2), в отчёте отметь, что сжатие было.

Почему. После сжатия исполнитель забывает правила и детали задачи. Отметка нужна, чтобы тим лид видел, где
искать такие ошибки.
