# Новый проект: завести место для задач

Открывай, когда в проекте нет `kit.toml` в корне или нет папки задач.

Статус: черновик от 19.10.2026, не испытан.

## 1. Что завести

Одним коммитом в основную ветку:

- `kit.toml` — из `assets/kit.example.toml`. Поправь основную ветку и пути, разделы тестов и границ оставь
  закомментированными до каркаса;
- `team/BACKLOG.md` — из `assets/backlog-template.md`;
- `team/tasks/`, `team/reports/` — пустые папки с `.gitkeep`;
- `team/templates/task.md` и `team/templates/report.md` — из `assets/task-template.md` и
  `assets/report-template.md`;
- `team/ACCESS.md` — из `assets/access-map-template.md`: каждый доступ, который уже есть у проекта, — блоком.
  Значения не пиши, только где они лежат;
- `team/RULES.md` — из `assets/rules-project-template.md`, пустой. Нет `~/.claude/kit/owner.md` — заведи его из
  `assets/rules-owner-template.md`, он вне git проекта. Что туда пишется — `owner-rules.md`.

Код подпроекта — две-три латинские буквы, `<CODE>_TASK_001` — первая задача. Один продукт — один код.

Почему. Скрипты сдачи и приёмки читают задание, отчёт и список задач по путям из `kit.toml`. Нет файла — скрипт
падает на первой же сдаче, и исполнитель обходит проверку вместо работы.

## 2. Проект уже живёт по своим правилам

Есть свой регламент, своя папка задач, свои шаблоны — не переделывай. Пропиши в `kit.toml` их пути и имена
разделов. Чего в проекте нет, но требует набор (раздел «Края» в отчёте), — добавь в его шаблон и скажи
владельцу одной строкой.

## 3. Нет git

Нет репозитория — спроси владельца и после «да» заведи его: ветки задач и проверки сдачи без git не работают.
