# Модель угроз продукта

Открывай, когда начинаешь проверку продукта, у которого её нет, или правка добавила новый вход снаружи.

Статус: черновик от 16.10.2026, не испытан.

## 1. Что это

Один файл в репозитории продукта, рядом со спецификацией: `docs/threat-model.md`. Шаблон —
`assets/threat-model-template.md`. Ты ведёшь его, исполнитель дописывает вход, который добавил.

В нём:
- **Входы снаружи** — маршруты, вебхуки, формы, бот, загрузки. Кто туда пишет.
- **Кто кому доверяет** — роли, системы, ключи. Что проверяется на каждой границе.
- **Что ценно** — данные клиентов, ключи, база знаний, деньги: платные вызовы и рассылки.
- **Что уже было** — найденные дыры и где закрыты. По ним охотник ищет соседей.
- **Что не проверено** — и почему.

Почему. Без модели угроз у одной команды ИИ-проверки 40 % находок были ложными, с хорошей — девять из десяти
подтверждались. Охотнику без неё не видно, кто снаружи и что ценно.

## 2. Как писать

1. Входы снаружи найди по коду, не по документу: декораторы маршрутов, обработчики событий, точки загрузки.
   Есть спецификация со схемой системы — сверь: каждая стрелка через рамку на схеме — строка здесь, и наоборот.
2. На каждой границе — одна строка: что проверяется и где в коде. «Не проверяется» — тоже ответ.
3. Ценное — с местом хранения: таблица, переменная окружения, папка. Значений не пишешь.
4. Коротко. Одна страница на продукт. Длинный файл охотник не дочитает.

## 3. Когда обновлять

- Новый вход снаружи, новая роль, новый внешний сервис — строка в той же задаче. Тим лид это видит при приёмке
  по поводу «новый вход снаружи».
- Подтверждённая находка — строка в «Что уже было».
- Проверка продукта целиком — пересмотр всего файла и дата в шапке.
