# Какой документ писать: виды документации

Открывай первым, когда просят «напиши документацию», а вид документа не назван. Здесь — как выбрать вид и чем
виды отличаются. Строение каждого вида — в своём файле, указатель — `README.md`.

## Содержание

1. Два вопроса для выбора
2. Четыре вида и их правила
3. Урок и инструкция — не одно и то же
4. Объяснение
5. Процесс и процедура
6. Остальные виды страниц
7. Перед тем как писать

## 1. Два вопроса для выбора

Схема называется Diátaxis. Два вопроса:

1. Читателю нужно действовать или понимать?
2. Читатель учится или работает?

| | Учится | Работает |
|---|---|---|
| **Действует** | Обучающий урок | Инструкция |
| **Понимает** | Объяснение | Справочник |

Вопросы задаются и к документу, и к отдельному абзацу. Абзац другого вида уходит на свою страницу, на его
месте остаётся ссылка.

Главное правило у всех источников: виды не смешиваются. Справочник с шагами и урок с теорией не служат никому.

## 2. Четыре вида и их правила

| Вид | Цель читателя | Что внутри | Чего нет |
|---|---|---|---|
| Обучающий урок | Получить навык | Один путь от начала до видимого итога | Выбора, веток, теории |
| Инструкция | Решить свою задачу | Шаги, условия «если», итог | Обучения, истории, объяснений |
| Справочник | Найти и сверить | Сухие записи одного вида | Шагов, мнений, рекламы |
| Объяснение | Понять, почему так | Связи, причины, варианты | Шагов и справочных данных |

Куда идти дальше:

- Инструкция, рунбук, быстрый старт, установка — `doc-howto.md`.
- Справочник, API, комментарии в коде — `doc-reference.md`.

## 3. Урок и инструкция — не одно и то же

| | Урок | Инструкция |
|---|---|---|
| Читатель | Учится, ничего не умеет | Умеет, занят своей задачей |
| Путь | Один, без выбора | С ветками «если» |
| Среда | Заданная автором | Какая есть у читателя |
| Простые действия | Расписаны | Предполагаются |
| Кто отвечает за сбой | Автор: каждый шаг обязан сработать у каждого | Читатель |

Правила урока:

- В начале показано, что получится. Обещания «вы узнаете» нет.
- После каждого шага виден результат. Сказано, что читатель увидит на экране.
- Объяснений минимум, глубокое — по ссылке.
- Урок проверен на живом человеке, который видит продукт впервые.

Строение урока по шаблону The Good Docs Project:

1. Что получится и для кого урок.
2. Что нужно до начала.
3. Шаги с результатом у каждого.
4. Итог.
5. Что дальше.

## 4. Объяснение

- Отвечает на вопрос «почему». Тема ограничена одним вопросом.
- Заголовок — название предмета: «Роли и права», «Как бот выбирает ответ».
- Внутри: связи с соседними частями, причины решений, рассмотренные варианты, сравнение, устройство.
- Размер по руководству GitLab: что это и зачем — один-два абзаца.
- Шагов нет. Нужны шаги — ссылка на инструкцию.

## 5. Процесс и процедура

Различие из метода Information Mapping:

| | Процесс | Процедура |
|---|---|---|
| О чём | Что происходит в системе | Что делает человек |
| Глагол | Настоящее время: «бот передаёт заявку» | Команда: «нажмите» |
| Вид документа | Объяснение, описание работы | Инструкция |

Смешение даёт текст, по которому нельзя ни понять систему, ни выполнить задачу.

## 6. Остальные виды страниц

Стандарт ISO/IEC/IEEE 26514:2022 и язык разметки DITA называют те же виды и добавляют свои:

| Вид страницы | Где описан |
|---|---|
| Понятие | Раздел 4 |
| Инструкция | `doc-howto.md` |
| Справочные данные, команды, API | `doc-reference.md` |
| Поиск неисправностей, сообщения об ошибках | `doc-errors.md` |
| Словарь терминов | Запись: термин и определение. Одно значение — одна запись |
| Частые вопросы | Отдельного правила в открытых источниках нет |

Проектные документы стоят вне этой схемы:

| Документ | Файл |
|---|---|
| README | `doc-readme.md` |
| Журнал изменений, заметки о выпуске | `doc-release.md` |
| Запись решения, описание архитектуры | `doc-architecture.md` |
| Юзер-кейс | `doc-use-case.md` |
| История, критерии приёмки | `doc-user-story.md` |
| Требование | `doc-requirements.md` |
| ТЗ | `doc-tz.md` |
| Руководства по ГОСТу | `doc-gost-manuals.md` |

## 7. Перед тем как писать

Порядок из стандарта простого языка ISO 24495-1:

1. Кто читает: что знает, каким языком говорит.
2. Зачем читает: выполнить шаги, принять решение, узнать о теме.
3. Где и как читает: устройство, время, внимание.
4. Какой вид документа подходит.
5. Какое содержание нужно этому читателю. Остальное не пишется.

После написания документ проверяют на читателе.
