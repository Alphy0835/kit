### 2.1. Анализ кода Python

#### Bandit
- Репозиторий: [PyCQA/bandit](https://github.com/PyCQA/bandit). Лицензия Apache-2.0. Полностью бесплатный.
- Живой: 8315 звёзд, push 12.10.2026, релиз 1.9.4 от 25.02.2026. Релизы редкие, но код правится.
- Что ловит: строит дерево программы и гонит по нему плагины. Классы: eval/exec, pickle, слабые хэши, shell=True, SQL из строк, отключённая проверка сертификатов, жёстко заданные пароли, небезопасная работа с временными файлами. Не видит потоков данных между функциями.
- Запуск: `docker pull ghcr.io/pycqa/bandit/bandit` (образ есть) или `pip install bandit` (в изолированной среде) и `bandit -r путь`. Ключи из [справочника](https://bandit.readthedocs.io/en/latest/man/bandit.html): `-ll` (средний уровень опасности и выше), `-iii` (только высокая уверенность), `-f sarif/json`, `-b baseline.json` (показать только новое по сравнению с базой), `-s` пропустить правило, `# nosec` на строке. Можно передать список файлов и `-` (код из stdin).
- Docker и сеть: не нужны.
- Скорость: нет замеров. Простой разбор файла.
- Ложные срабатывания: уровни опасности и уверенности для отсева, `# nosec`. Сравнение на синтетическом наборе Python (препринт [arXiv 2608.07026](https://arxiv.org/pdf/2608.07026), 2026, не прошёл рецензию): точность Bandit около 71% против 83–85% у Semgrep и CodeQL. Это одна работа, с оговорками.
- По diff: на уровне файлов (передать `git diff --name-only`). На уровне строк нет. Альтернатива: baseline `-b`.

#### Правила Ruff `S` (flake8-bandit внутри Ruff)
- Репозиторий: [astral-sh/ruff](https://github.com/astral-sh/ruff). MIT. Бесплатный.
- Живой: 50121 звезда, push 16.10.2026, релиз 0.17.1 от 15.10.2026.
- Что ловит: около 70 правил с кодами S1xx–S7xx: assert, пароли в коде, `pickle`, слабые хэши, `eval`, `shell`, SQL из строк, Jinja2 без автоэкранирования, `requests` без таймаута и т. д. ([список правил](https://docs.astral.sh/ruff/rules/#flake8-bandit-s)). По странице документации не выяснил, насколько покрытие совпадает с настоящим Bandit; часть правил в режиме preview.
- Запуск: `ruff check --select S файлы` (по памяти, на странице правил этой команды нет). Если Ruff у нас уже стоит для стиля, это почти бесплатно.
- Docker, сеть: не нужны. Скорость: Ruff самый быстрый в этом классе, но замера в документации нет.
- Ложные срабатывания: `# noqa: S101` на строке, исключения в `pyproject.toml`.
- По diff: на уровне файлов, как у Bandit.

#### Semgrep Community Edition
- Репозиторий: [semgrep/semgrep](https://github.com/semgrep/semgrep). Движок LGPL-2.1, бесплатный. 17095 звёзд, push 16.10.2026, релиз v1.181.0 от 14.10.2026.
- ВНИМАНИЕ, лицензия правил ([semgrep-rules](https://github.com/semgrep/semgrep-rules)): «Semgrep Rules License v1.0». Репозиторий правил на GitHub помечен как «NOASSERTION». Я прочитал [текст лицензии](https://semgrep.dev/legal/rules-license). Свободно можно для собственных внутренних целей бизнеса. Нельзя: раздавать правила другим, предоставлять их другим как сервис, снимать пометки об авторстве, передавать права. Из этого для нас: гонять правила у себя — можно. Класть копию правил в общий репозиторий набора скилов или отдавать заказчику внутри поставки — нельзя. Различие между правилами из реестра и из репозитория на странице лицензии не разобрано.
- Что ловит: шаблоны по структуре кода, Python, JS/TS и ещё десятки языков. Свои правила пишутся просто, их можно держать у себя. Бесплатная версия, по вторичным источникам, анализирует в пределах одного файла и одной функции; межфайловый анализ и более полный поиск потоков данных — платный Semgrep Code ([FAQ Semgrep](https://semgrep.dev/docs/faq/overview), вторичные обзоры). Вторичный источник: на тестовых наборах бесплатная версия нашла 44–48% уязвимостей против 72–75% у платной ([appsecsanta](https://www.appsecsanta.com/semgrep)); числа связаны с вендором, перепроверять надо.
- Запуск: `pip install semgrep` или образ `semgrep/semgrep`; `semgrep scan --config p/python --config p/javascript путь`. Команды и имена наборов правил по памяти, не проверены по документации. Наборы из реестра качаются из сети; нужна ли учётная запись для них, не выяснил.
- Docker: по желанию. Сеть: для загрузки правил нужна (если правила скачаны или свои, сеть не нужна). Телеметрию можно отключить (по памяти, не проверено).
- Скорость: нет замеров.
- Ложные срабатывания: в исследовании [arXiv 2601.22952](https://arxiv.org/pdf/2601.22952) (многоязычный набор, не только Python) у Semgrep доля ложных срабатываний 74,8% при полноте 90,4%. У CodeQL точность выше, но доля ложных тоже высокая (68,2%). Препринт. Вывод: ждать надо шума и разбирать руками.
- По diff: у Semgrep есть режим сравнения с базовым коммитом (`--baseline-commit`; по памяти, не проверено по документации).
- Форк: [opengrep/opengrep](https://github.com/opengrep/opengrep), LGPL-2.1, 3193 звезды, релиз v1.31.0 от 15.10.2026. Создан в январе 2025 как свободная замена, возвращает часть функций, которые Semgrep убрал из бесплатной версии (вторичный источник: обзор appsecsanta). Правила Semgrep он читает, но те же условия лицензии правил остаются. Свои правила писать можно без ограничений.

#### CodeQL
- Репозиторий запросов: [github/codeql](https://github.com/github/codeql), MIT. Но сам запуск (CLI) идёт под отдельными условиями ([LICENSE.md в codeql-cli-binaries](https://github.com/github/codeql-cli-binaries/blob/main/LICENSE.md)): бесплатно для открытого кода (лицензия OSI), для учёбы и исследований. Для частного репозитория или закрытого кода — запрещено без платной лицензии GitHub Advanced Security (так написано в этих условиях; их новое название «Code Security», подтверждение только из неофициальной копии документации).
- Вывод: **нам не подходит**. Наши репозитории частные (в том числе клиентский код). Не включать в набор. Не использовать даже «чтобы посмотреть» на закрытом коде.
- Качество (если бы можно): в препринте [arXiv 2608.07026](https://arxiv.org/pdf/2608.07026) точность 84,5%; в [arXiv 2601.22952](https://arxiv.org/pdf/2601.22952) лучшая точность из трёх, но 68% ложных.

#### Pysa (Pyre)
- [facebook/pyre-check](https://github.com/facebook/pyre-check): в архиве, последний релиз v0.9.23 от 29.10.2024. Pysa вынесен в [facebook/Pysa](https://github.com/facebook/Pysa) (MIT, 29 звёзд, push 16.10.2026). Анализ потоков данных (откуда пришли данные и куда попали), но настройка тяжёлая, нужна модель правил. Глубоко не изучал. Не включён.

### 2.3. Секреты

#### Betterleaks (преемник Gitleaks)
- [betterleaks/betterleaks](https://github.com/betterleaks/betterleaks). MIT. Бесплатный. 2247 звёзд, push 15.10.2026, релиз v1.9.0 от 29.09.2026.
- Почему он: автор Gitleaks пишет в README, что [Gitleaks](https://github.com/gitleaks/gitleaks) «завершён по функциям», новые релизы только исправления безопасности, а сам он переключается на Betterleaks. Вторичные источники ([BleepingComputer](https://www.bleepingcomputer.com/news/security/betterleaks-a-new-open-source-secrets-scanner-to-replace-gitleaks/)): Betterleaks MIT, проект заменяет Gitleaks, совместим с его конфигами и ключами, обнаруживает по токенам BPE, а не по энтропии. Заявленная полнота 98,6% против 70,4% у энтропии на наборе CredData — это цифры самих авторов, независимо не перепроверены.
- Gitleaks: MIT, 30026 звёзд, релиз v8.30.1 от 21.03.2026, push 30.09.2026.
- Что ловит: ключи и токены по шаблонам и словарю (облака, мессенджеры, платёжные системы, общие `api_key=`). Смотрит историю git.
- Запуск (по README Gitleaks): `gitleaks git` (история, диапазон через `--log-opts "ветка_основная..HEAD"`), `gitleaks dir` (папка), `gitleaks stdin`. Образы: `ghcr.io/gitleaks/gitleaks`, `zricethezav/gitleaks`. Хук pre-commit. Для Betterleaks команды те же по заявлению авторов (проверить на первом запуске).
- Docker, сеть: Docker по желанию, сеть не нужна.
- Скорость: нет замеров.
- Ложные срабатывания: комментарий `gitleaks:allow` в строке, файл `.gitleaksignore` по отпечаткам, список разрешений в конфиге (путь, регулярка, стоп-слова), baseline (`--baseline-path`: показывать только новое). Код возврата 1 при находке.
- По diff: да, диапазон коммитов.

#### TruffleHog
- [trufflesecurity/trufflehog](https://github.com/trufflesecurity/trufflehog). Лицензия **AGPL-3.0**: запуск как отдельной программы можно, но встраивать в наш код или сервис нельзя. 28537 звёзд, push 16.10.2026, релиз v3.99.2 от 08.10.2026.
- Отличие: умеет проверять, действует ли найденный ключ (режим `--results=verified`). Для этого он сам обращается к сервисам-владельцам ключей по сети с этим ключом. Это надо учитывать: ключ выйдет за пределы машины, а при опасности (боевой ключ) такой запрос лучше не делать. По README это видно из названия режима; точный перечень сервисов не смотрел. Для безопасной работы: `--results=unverified` или без проверки (флаг по памяти, не проверен).
- Запуск: `docker run --rm -it -v "$PWD:/pwd" trufflesecurity/trufflehog:latest ...`; `trufflehog git file://. --since-commit main --branch HEAD --results=verified,unknown --fail`; выход 183 при находке. Подробности — в [README](https://github.com/trufflesecurity/trufflehog).
- По diff: да, `--since-commit`.
- Вывод: для нас достаточно одного сканера секретов (Betterleaks/Gitleaks). TruffleHog добавлять, если нужна проверка «ключ ещё жив?» в локальном режиме и только против тестовых ключей.

#### detect-secrets
- [Yelp/detect-secrets](https://github.com/Yelp/detect-secrets). Apache-2.0. 4653 звезды, push 02.04.2026, но последний релиз v1.5.0 от 06.05.2024 — давний.
- Работает с текущим деревом файлов, не с историей. Авторы пишут, что это не надёжный способ, он не ловит многострочные секреты и простые пароли без ключевых слов. Не рекомендую: Betterleaks закрывает ту же задачу и смотрит историю.

### 2.4. Зависимости

#### OSV-Scanner
- [google/osv-scanner](https://github.com/google/osv-scanner). Apache-2.0. Бесплатный. 11196 звёзд, push 15.10.2026, релиз v2.7.0 от 12.10.2026.
- Что ловит: известные уязвимости в зависимостях по lock-файлам: Python и npm (в числе поддерживаемых 11+ экосистем), образы Docker (слои), пакеты ОС. Есть «анализ вызовов» (вызывается ли уязвимая функция) — меньше шума, но не для всех языков ([README](https://github.com/google/osv-scanner)).
- Запуск: `osv-scanner scan source -r путь` (бинарник или `go install`). Образ есть (по памяти).
- Сеть: **нужна** (запрос в базу OSV). Docker не нужен.
- Скорость: нет замеров.
- Ложные срабатывания: база OSV собрана из первоисточников (GitHub Advisory, ОС-списки), авторы заявляют высокое качество; ложные срабатывания остаются для случаев «версия под риском, но функция не вызывается».
- По diff: сканирует весь lock-файл целиком, он быстрый. Запускать, когда тронули `requirements*.txt`, `poetry.lock`, `package-lock.json`.
- Python без lock-файла (только `requirements.txt` с `>=`): уязвимые версии определяются неточно. Закреплять версии.

#### pip-audit
- [pypa/pip-audit](https://github.com/pypa/pip-audit). Apache-2.0. 1381 звезда, push 15.10.2026, релиз v2.10.1 от 10.06.2026.
- Python-специфичный. Читает требования или окружение (`pip-audit -r requirements.txt`, ключ `-s osv` для базы OSV вместо PyPI), умеет автоисправление `--fix`, игнор известного `--ignore-vuln`. Источники: PyPI JSON API и OSV ([README](https://github.com/pypa/pip-audit)).
- Сеть нужна. Docker нет. Берёт кэш pip.
- Роль: вторая проверка Python после OSV-Scanner. Если надо выбрать один, берём OSV-Scanner.

#### npm audit
- Встроен в npm, бесплатен, в документации отдельно не читал. По памяти: `npm audit` использует базу GitHub Advisory, нужна сеть, ругается на транзитивные зависимости, которые часто невозможно исправить. Не проверено.

#### Trivy (как сканер зависимостей)
- См. 2.7. `trivy fs путь` по умолчанию ищет уязвимости и секреты ([документация](https://trivy.dev/latest/docs/target/filesystem/)). Для Python опирается на lock-файлы.

#### OWASP Dependency-Check
- [dependency-check/DependencyCheck](https://github.com/dependency-check/DependencyCheck). Apache-2.0. 7736 звёзд, релиз v13.0.0 от 03.08.2026. Основной язык — Java; для остальных использует дополнительные источники (npm audit, RetireJS, Bundler Audit). Первая загрузка базы может занять десять минут и больше ([страница проекта](https://owasp.org/www-project-dependency-check/)). Не вошёл в набор: для Python и JS OSV-Scanner проще и точнее. Про шум от сопоставления по CPE и про ключ NVD API — по памяти, на странице нет.

- Встроен в GitHub. - Что даёт ([README](https://github.com/ossf/scorecard)): оценку 0–10 по проверкам: защита веток, обзор кода, права токена в workflow, опасные workflow, закрепление зависимостей, наличие политики безопасности, подписанные релизы, «поддерживается ли проект», известные уязвимости и т. д. Критичные проверки: Dangerous-Workflow, Webhooks. Для пакета с PyPI или npm есть ключи `--pypi=имя`, `--npm=имя`, которые находят репозиторий исходников.
- Запуск: `scorecard --repo=github.com/владелец/репо` с переменной `GITHUB_AUTH_TOKEN`; образ Docker есть. Нужна сеть и токен GitHub (чтение публичного). Частные репозитории: в README не сказано. Windows: авторы пишут, что поддержка может быть проблемной, поддерживаются Linux и macOS — запускать в Docker.
- Ложные срабатывания: авторы прямо пишут, что проверки — эвристики с ложными срабатываниями и пропусками; оценка не является требованием.
- Без установки: готовые оценки открыты по адресу API `api.securityscorecards.dev` и через deps.dev (адрес API по памяти).

#### deps.dev
- Сервис Google, [описание API v3](https://docs.deps.dev/api/v3/). Отдаёт: версии и даты публикации, признак «устарел», лицензии, список уязвимостей OSV, оценку Scorecard, граф зависимостей. Системы: PyPI, npm, Go, Maven, Cargo, NuGet, RubyGems. Запрос: `GET https://api.deps.dev/v3/systems/pypi/packages/имя`.
- Условия: подчиняется условиям Google API; в описании не сказано, бесплатный ли он и есть ли лимиты; кэшировать данные разрешено. Что вернёт для несуществующего пакета (ожидается 404) — не написано, проверять первым запросом.
- Установки нет, достаточно `curl`. Сеть нужна.

#### Проверка, что пакет существует (галлюцинации имён, «slopsquatting»)
- Проблема: ИИ придумывает названия пакетов, и злоумышленник может занять такое имя. USENIX Security 2025 (Spracklen и др.; препринт arXiv 2406.10279): доля несуществующих пакетов 5,2% у коммерческих моделей и до 21,7% у открытых, часть названий повторяется (43% повторялись при десяти повторах одного запроса). Пересказ по вторичным источникам ([TechRepublic](https://www.techrepublic.com/article/news-slopsquatting-vibe-coding-ai-cybersecurity-risk/)); точную ссылку на труды USENIX не сверял. Перепроверка 2026 года на новых моделях (препринт, [alphaxiv 2605.17062](https://www.alphaxiv.org/abs/2605.17062)): 4,6% у Claude Haiku 4.5, 6,1% у GPT-5.4-mini; 127 одинаковых выдуманных имён у пяти моделей.
- Как проверять без установки: запрос `https://pypi.org/pypi/ИМЯ/json` (404 — пакета нет; по памяти) или `https://registry.npmjs.org/ИМЯ` (по памяти) — и сразу смотреть дату создания, число релизов, ссылку на репозиторий. **Существует** не значит **безопасен**: именно новое имя с одним релизом — признак того, что его занял атакующий. Сочетание: deps.dev (дата первой публикации) + Scorecard репозитория + OSV.
- garak имеет пробу `packagehallucination` для проверки самой модели.

#### Socket
- [socket.dev](https://socket.dev) анализирует поведение пакетов (скрипты установки, сеть, обфускация). По вторичным источникам ([agentdeals.dev](https://agentdeals.dev/vendor/socket-dev), [usagepricing.com](https://usagepricing.com/blueprint/activity/socket-2026-07-29-packaging)): бесплатный уровень есть, для открытых проектов бесплатно; частные репозитории — бесплатный уровень с лимитом (называют 1000 сканов в месяц и до 5 участников; другой источник называет лимит 10 000 зависимостей — путают сканы и зависимости). Платные тарифы от 25 долларов за разработчика в месяц. Живую страницу цен мои источники не открыли — **перепроверить** до использования. Это облачный сервис: данные о зависимостях уходят в него. В набор как обязательное не включён.

## 3. Что и когда запускать

Запуск идёт на нашей машине или на локальном стенде. Минуты GitHub Actions (на бесплатном тарифе их мало) не тратим: в Actions ставим максимум Scorecard-проверки и, при желании, OSV по расписанию; остальное локально. Trivy в Actions не запускать (раздел 4).

### А. На каждой сдаче задачи: быстро, по правке

| Что тронули | Что запустить |
|---|---|
| любой `.py` | Bandit по изменённым файлам (`-ll -iii`) или Ruff `S`; Semgrep CE по diff |
| любой `.js/.ts` | Semgrep CE по diff; eslint-plugin-security по файлам, смотреть только новые |
| любой коммит | Betterleaks/Gitleaks по диапазону коммитов ветки |
| `requirements*`, lock-файлы, `package*.json` | OSV-Scanner по проекту (быстро), при желании pip-audit |
| `Dockerfile`, Compose | Hadolint по файлу; `trivy config` |
| `.github/workflows/*` | вручную посмотреть права токена и триггеры; при желании Checkov или Scorecard |

Результат: список находок. Только новые находки по diff считаются дефектом задачи; старые — отдельной записью.

### Б. Перед выкладкой, на локальном стенде

1. Запустить стенд из того образа, который пойдёт в бой.
2. ZAP baseline (пассивный), затем ZAP API scan, если есть схема OpenAPI; иначе активный скан по списку адресов вручную.
3. Nuclei с ограничением скорости, теги: раскрытие информации, неверные настройки, известные CVE; без `-dashboard`.
4. Schemathesis по схеме OpenAPI, если она есть.
5. `trivy image` и Dockle по собранному образу; полный Hadolint.
6. Semgrep CE и Bandit по всему коду (не только по diff); Betterleaks по всей истории; OSV-Scanner по всем lock-файлам.
7. По желанию: ffuf по панели (поиск забытых адресов), sqlmap по формам и параметрам, которые ходят в SQL, только на копии тестовой базы.
8. Если менялись промпты, база знаний, права ботов: promptfoo red team по плагинам RAG-утечка, BOLA, BFLA, SSRF, SQL (с отключённой удалённой генерацией и учебными данными).

### В. По поводу

| Повод | Что запустить |
|---|---|
| Новая библиотека или образ | Проверка существования в PyPI/npm, дата первой публикации и число релизов (deps.dev); Scorecard репозитория; OSV по версии; лицензия (deps.dev); для образа `trivy image` и Dockle |
| Новый вход снаружи (вебхук Telegram/MAX/Bitrix24, новый REST-метод, новая форма) | ZAP API scan или full по этому входу; Schemathesis по его схеме; sqlmap и ffuf по новым адресам и параметрам; проверка подписи вебхука вручную |
| Изменение работы с ИИ (промпт, поиск по базе, инструменты бота) | promptfoo red team; garak для общего прогона |
| Новая роль или право в панели | ручная проверка BOLA/BFLA; promptfoo `bola`/`bfla` для ИИ-части; ZAP с двумя сессиями — вручную |
| Выбор готового решения для исполнителей (скил, плагин, MCP-сервер) | Scorecard, deps.dev, проверка существования, чтение кода на сетевые вызовы и скрипты установки; Socket (если лимиты подойдут) |
