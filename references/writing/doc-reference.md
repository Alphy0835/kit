# Справочник: описание команд, настроек, API, функций в коде

Открывай, когда описываешь то, что читатель ищет и сверяет, а не читает подряд: параметры, команды, методы
API, коды ошибок, комментарии к функциям.

## Общие правила справочника

- Справочник описывает, шагов и объяснений в нём нет. Шаги — в инструкции, «почему так» — в объяснении.
- Строение повторяет строение продукта: раздел на команду, на метод, на экран.
- Все записи одного вида написаны одинаково: те же части, тот же порядок.
- Тон сухой и точный. Оценок, советов и рекламы нет.
- Пример короткий и только показывает запись. Задачу он не решает.
- Названы значения по умолчанию, пределы и ограничения.
- Справочник, собранный из кода, руками не правится: правится код.

## Запись о команде, настройке, параметре

Таблица из двух колонок: название и описание в одно предложение. Для настройки — ещё тип, значение по
умолчанию, допустимые значения.

Описание не повторяет название. Было: «`timeout` — таймаут». Стало: «`timeout` — сколько секунд бот ждёт
ответа сервера. По умолчанию 30».

## Страница об элементе API или библиотеки

Части по порядку, по руководству Microsoft:

1. Заголовок: имя и вид — «Метод `createOrder`».
2. Описание: 1–2 предложения, имя не повторяется.
3. Синтаксис.
4. Параметры: обязателен ли, что принимает.
5. Что возвращает.
6. Ошибки и исключения.
7. Примечания.
8. Пример.
9. Требования: версия, права.
10. Смотри также.

## Описание HTTP API

Общая страница, по шаблону The Good Docs Project:

- базовый адрес;
- как проходит авторизация;
- версия;
- постраничная выдача;
- пределы частоты запросов;
- коды ответа;
- вид ошибки.

На каждый метод:

1. Адрес и HTTP-метод.
2. Описание.
3. Кому доступен.
4. Запрос: параметры пути, строки запроса, заголовков, тело.
5. Пример запроса.
6. Ответ: поля.
7. Пример ответа.

Страница «первый запрос»: что нужно заранее, авторизация, базовый адрес, запрос и ответ, что дальше.

Описание собирается из кода и показывается страницей Swagger — правила в `doc-api.md`.

Машинное описание — формат OpenAPI. В нём обязательны версия формата, название и версия описания, а также
хотя бы одно из трёх: пути, компоненты, вебхуки.

## Комментарий к функции в коде

Правила Python, PEP 257 и руководство Google:

- Первая строка — итог одной фразой, до 80 знаков, с точкой. Затем пустая строка и подробности.
- Комментарий нужен функции, которая входит в открытый интерфейс, велика или делает неочевидное.
- По комментарию можно написать вызов, не читая код.
- Части: аргументы, что возвращает, какие ошибки бросает.
- Стиль первой строки один на файл: «Вернуть пользователя» либо «Возвращает пользователя».
- Сигнатура в комментарии не повторяется.
- Комментарий внутри кода объясняет замысел, а не пересказывает строку.
